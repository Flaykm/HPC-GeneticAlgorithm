## Задача

Реализовать генетический алгоритм для поиска коэффициентов аппроксимирующего полинома:
- **Входные данные**: Набор точек (700 шт.), сгенерированных на основе полинома 4-й степени с добавлением шума.
- **Реализация**: 
    - Генетический алгоритм, полностью перенесенный на GPU.
    - Оценка фитнес-функции (MSE), скрещивание (Crossover) и мутация (Mutation) реализованы в виде CUDA-kernels.
- **Выходные данные**: Коэффициенты полинома, итоговое значение фитнес-функции, время вычисления и графики сходимости.

---

## Реализация

В виде альтернативы `cuRAND` используется `numba.cuda.random`. Как аналог `Thrust` был использован `cupy`.

В работе реализован параллельный генетический алгоритм, где основные этапы эволюции выполняются на `GPU`:

- **Fitness Evaluation** (`kernel_evaluate_fitness`) — каждый поток на GPU вычисляет суммарную квадратичную ошибку для конкретной особи из популяции на всем наборе входных точек.
- **Crossover** (`kernel_crossover`) — параллельное создание нового поколения. Используется одноточечный оператор скрещивания. Случайные числа генерируются непосредственно на GPU с помощью `xoroshiro128p`.
- **Mutation** (`kernel_mutation`) — внесение случайных изменений в гены. Реализована адаптивная мутация: масштаб изменений (`mutation_scale`) уменьшается с каждой генерацией для более тонкой настройки решения в конце обучения.
- **Особенности**: 
    - Использование **элитизма**: лучшие особи (elite fraction) переносятся в следующее поколение без изменений.
    - Генерация случайных чисел происходит на стороне GPU, что исключает накладные расходы на передачу массивов случайных чисел с CPU.

## Выводы

1.  **Эффективность GPU** — использование CUDA позволило обрабатывать популяцию в 2000 особей на протяжении 1000 генераций всего за ~3.6 секунды.
2.  **Точность** — найденные коэффициенты практически идентичны исходным (например, $c_1 \approx -0.300076$ при истинном $-0.3$). Небольшие отклонения обусловлены зашумленностью входных данных.
3.  **Сходимость** — график фитнес-функции показывает экспоненциальную сходимость. На ранних этапах алгоритм быстро находит область оптимума, а в конце плавно уточняет результат.
4.  **Адаптивность** — механизм уменьшения `mutation_scale` позволил избежать разбрасывания решения на поздних итерациях и помог алгоритму стабилизироваться на найденном минимуме.
